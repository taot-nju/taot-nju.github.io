❶ 核心思考：大模型与 Agent 时代的数据设计演进

随着大语言模型（LLM）与 AI Agent（智能体）的爆发式发展，我们正处于命令行与数据交互模式的转型节点：

  • 过去（面向人类设计 / Human-Centric）： 传统 CLI 工具（如 column -t）的核心诉求是视觉舒适度与人类可读性。人类眼睛需要对齐的列、漂亮的边框、高亮颜色以及合理的留白，才能快速定位数据。

  • 未来（面向 Agent 设计 / Agent-Centric）： 系统与工具的接口将越来越频繁地被 Agent 调用与解析。对 Agent 而言，完美的视觉对齐不仅毫无意义，反而会引入无谓的 Token 开销与解析噪音。Agent 需要的是标准、无歧义、低冗余的高密度数据结构（如原始 CSV、JSON、YAML）。

💡 小学生也能听懂的比喻

给人类看的数据，就像“带精美插画和漂亮边框的童话绘本”。字与字之间空得很开，排版整整齐齐，小朋友看起来眼睛舒服、不费力。

给 AI/Agent 看的数据，就像“乐高积木块”。不需要画漂亮的包装盒，每一个积木块上都有固定的接口卡扣（比如逗号 ,）。AI 根本不需要看它“漂不漂亮”，只要卡扣对应正确，它一秒钟就能把所有积木拼好！如果加了太多用来好看的填充空格，反而会像给积木裹了泡沫塑料，让 AI 拿起来变费劲。

❷ 真实案例佐证：人类与 Agent 的“偏好差异”

  • 对人类： 错位混杂。70 和 temperature.gpu 字符长度不一，导致后面的逗号无法对齐，视觉体验较差。

  • 对 Agent： 极度友好！ 采用标准 CSV 逗号分隔，没有任何多余的连续填充空格。Agent 只需要调用简单的 split(',') 或 CSV 解析器即可 100% 精确提取每个字段，且节省 Token 消耗。
